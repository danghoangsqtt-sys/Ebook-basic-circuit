Đồ Án — Integration Test & Calibration

Test toàn hệ thống theo yêu cầu SRS, calibration cảm biến và xác nhận hiệu suất đáp ứng thông số kỹ thuật.

🔬 Testing: 90 phút📊 Calibration: 60 phút
🎯 Mục tiêu bài học
  • Viết và chạy Test Plan đầy đủ theo yêu cầu SRS
  • Calibration offset cho cảm biến nhiệt độ — so sánh với nhiệt kế chuẩn
  • Calibration ADC pin bằng đa điểm (multi-point calibration)
  • Đo và validate thời gian pin thực tế vs ước tính
  • Stress test: chạy liên tục 24h — có crash không?
  • Regression test — sau khi sửa bug, test lại toàn bộ
  • Viết Test Report đơn giản — kết quả P/F cho từng FR

1. Test Plan — Từ SRS đến bảng test

Bảng dưới là kế hoạch đo trên thiết bị đã xác minh, không phải kết quả đã chạy. Nếu chưa có board, dùng dữ liệu giả lập có đầu vào và đầu ra kỳ vọng được lưu lại để thử logic, đánh dấu các hàng đo cảm biến/pin/độ bền là chưa xác minh phần cứng; không ghi PASS vật lý từ dữ liệu mô phỏng.

2. Calibration Cảm Biến — Nhiệt độ Offset

// Calibration offset — so sánh với chuẩn
// Với phần cứng: đo cùng lúc với nhiệt kế tham chiếu đã biết độ chính xác
// Với dữ liệu giả lập: dùng cặp mẫu đã công bố, không gọi là hiệu chuẩn cảm biến thật

float TEMP_OFFSET = -1.5;  // Điều chỉnh sau khi đo

float getCalibratedTemp() {
  return bme.readTemperature() + TEMP_OFFSET;
}

// Multi-point calibration (3 điểm: 20°C, 25°C, 30°C)
// Đo cả 3 điểm, lấy trung bình offset:
// T_error_20 = 20.0 - T_sensor_at_20
// T_error_25 = 25.0 - T_sensor_at_25
// T_error_30 = 30.0 - T_sensor_at_30
// OFFSET_AVERAGE = (T_error_20 + T_error_25 + T_error_30) / 3

3. Stability Test — kế hoạch chạy 24 giờ

⏱ Phân tích log; đo bền thật khi có thiết bị được duyệt

  1. Định nghĩa bản ghi mỗi 60 giây: timestamp, giá trị cảm biến, heap free, WiFi RSSI và trạng thái reset. Với nhánh mô phỏng, tạo chuỗi mẫu t=0, 60, 120 giây và nhiệt độ 25, 36, 25°C; xác nhận logic cảnh báo chỉ bật ở mẫu vượt 35°C rồi lưu input/output dự kiến.

  2. Kiểm tra bộ phân tích log bằng cách bỏ mẫu t=60 giây: chương trình phải báo thiếu mẫu; thêm cờ reset tại t=120 giây: phải phân loại sự kiện reset. Đây là kiểm logic phân tích log, không chứng minh chạy bền 24 giờ.

  3. Nếu có board đã được kiểm nguồn và pin, chạy liên tục 24 giờ và lưu log thực; so sánh khoảng trống, heap, RSSI, dòng và nhiệt với NFR của chính đồ án. Giới hạn dòng/nguồn và người giám sát phải theo hồ sơ phần cứng.

  4. Khi log thật có reset, ghi esp_reset_reason() để phân biệt WDT, panic hay brownout. Chỉ kết luận Stability PASS khi có log thực đủ thời lượng và tiêu chí đạt.

Điền bảng Test Plan theo bằng chứng hiện có. Hàng nào thử logic bằng dữ liệu giả lập, hàng nào cần đo thật? Không gộp kết quả hai loại thành cùng một PASS.

Từ cặp mẫu giả lập nhiệt kế tham chiếu 25,0°C và cảm biến 26,5°C, tính TEMP_OFFSET; nêu vì sao giá trị này chưa chứng minh độ chính xác của cảm biến thật hoặc toàn dải đo.

Sau khi điền bảng test, phân loại failures theo: (a) Hardware bug: linh kiện hỏng, hàn kém → rework; (b) Firmware bug: logic sai, race condition → fix code; (c) Configuration bug: ngưỡng sai, timeout sai → sửa config.h; (d) Performance miss: chậm hơn yêu cầu → tối ưu code hoặc điều chỉnh NFR nếu có lý do kỹ thuật. Tất cả failures phải có ticket và kế hoạch sửa trước khi demo.
