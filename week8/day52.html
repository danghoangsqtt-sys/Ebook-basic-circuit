FreeRTOS — Đa Nhiệm Thực Thời Trên ESP32

Vượt qua giới hạn của vòng lặp đơn — FreeRTOS cho phép nhiều tác vụ chạy song song với priority và timing chính xác.

⏱ Lý thuyết: ~35 phút💻 Thực hành: 60 phút
🎯 Mục tiêu bài học
  • Hiểu RTOS là gì — khác gì với vòng lặp while(1) thông thường
  • Tạo và quản lý Task trong FreeRTOS (ESP32 built-in)
  • Priority và Scheduling — task nào được CPU khi nào
  • vTaskDelay() vs delay() — RTOS-friendly delay
  • Queue — truyền dữ liệu an toàn giữa các task
  • Semaphore/Mutex — bảo vệ tài nguyên chia sẻ
  • Giám sát stack: uxTaskGetStackHighWaterMark()
  • Biết khi nào cần RTOS, khi nào millis() scheduler đủ

2. Task cơ bản trong FreeRTOS

// ESP32 FreeRTOS — 2 task song song
// Task đọc sensor mỗi 2s, task update display mỗi 500ms

float sensorTemp = 0;
SemaphoreHandle_t dataMutex;  // Bảo vệ sensorTemp

void taskSensor(void* param) {
  for (;;) {  // Vòng lặp vô hạn — thay thế loop()
    float t = bme.readTemperature();
    
    xSemaphoreTake(dataMutex, portMAX_DELAY);  // Lock
    sensorTemp = t;
    xSemaphoreGive(dataMutex);                 // Unlock
    
    vTaskDelay(pdMS_TO_TICKS(2000));  // Suspend 2s, nhường CPU
  }
}

void taskDisplay(void* param) {
  for (;;) {
    float temp;
    xSemaphoreTake(dataMutex, portMAX_DELAY);
    temp = sensorTemp;
    xSemaphoreGive(dataMutex);
    
    oled.clearDisplay();
    oled.printf("%.1f C", temp);
    oled.display();
    
    vTaskDelay(pdMS_TO_TICKS(500));  // Refresh 2×/giây
  }
}

void setup() {
  dataMutex = xSemaphoreCreateMutex();
  
  // Tạo task: name, stack size, param, priority, handle, core
  xTaskCreatePinnedToCore(taskSensor,  "Sensor",  4096, NULL, 2, NULL, 1);
  xTaskCreatePinnedToCore(taskDisplay, "Display", 4096, NULL, 1, NULL, 1);
  // Priority 2 > Priority 1 → Sensor task ưu tiên cao hơn
}

void loop() {}  // FreeRTOS quản lý vòng lặp

3. Queue — Truyền dữ liệu giữa tasks

// Queue: sensor → logger task
QueueHandle_t dataQueue = xQueueCreate(10, sizeof(float));  // 10 item

// Trong taskSensor:
float temp = bme.readTemperature();
xQueueSend(dataQueue, &temp, 0);  // Gửi vào queue, không chờ

// Trong taskLogger:
float received;
if (xQueueReceive(dataQueue, &received, pdMS_TO_TICKS(100))) {
  logToSD(received);  // Ghi SD khi có dữ liệu mới
}

Khi nào cần Mutex thay vì Queue? Cho ví dụ cụ thể trong dự án IoT.

2: Queue: dùng khi muốn chuyển data từ producer → consumer một chiều. Ví dụ: sensor task gửi readings vào queue → logger task đọc và ghi SD. Mutex: dùng khi nhiều task cùng đọc/ghi vào tài nguyên chia sẻ hai chiều. Ví dụ: biến float currentTemp được đọc bởi display task và ghi bởi sensor task đồng thời → cần mutex để tránh race condition (đọc giá trị bị sửa nửa chừng). Rule of thumb: Queue cho data flow, Mutex cho shared resource protection.
